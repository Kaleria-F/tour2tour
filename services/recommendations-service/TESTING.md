# Тестирование recommendations-service

## Что покрыто тестами

- валидация входного профиля пользователя;
- правила расчёта `budget_bonus` и лимита выдачи;
- diversity rerank, чтобы в начале выдачи не было однотипных карточек;
- endpoint `/recommendations/personalized`:
  - исключение мест с устойчивым негативным сигналом;
  - использование пользовательских сигналов и дефолтных весов при пустом профиле;
- endpoint `/recommendations/suggestions`:
  - выбор шаблона подсказок;
  - подстановка `location`, `latitude`, `longitude`;
  - fallback на дефолтные рекомендации.

## Как запускать локально

Из директории `services/recommendations-service`:

```bash
python -m pip install -e .
python -m pip install pytest
pytest
```

Если проект запускается через Poetry/uv, допустим эквивалентный запуск:

```bash
poetry install
poetry run pytest
```

или

```bash
uv sync --group dev
uv run pytest
```

## Процесс тестирования

1. Перед изменением логики рекомендаций запускаются unit/API-тесты сервиса.
2. При изменении формулы скоринга обновляются тесты на бонусы и ранжирование.
3. При изменении интеграции с `places-service` или `interactions-service` проверяются сценарии:
   - есть пользовательские сигналы;
   - сигналов нет;
   - место должно быть исключено из выдачи.
4. Перед релизом дополнительно выполняется ручная проверка:
   - пустой профиль;
   - профиль с интересами и бюджетом;
   - `near_route=true`;
   - разные `stage_type/subtype` для `/recommendations/suggestions`.
5. Регрессией считается любое изменение порядка выдачи, лимита, exclusion-логики или структуры ответа без осознанного обновления тестов и API-контракта.
