# Архитектура микросервисов Tour2Tour

## Границы сервисов
- **auth-service**: регистрация, логин, профиль, 2FA, предпочтения пользователя.
- **trips-service**: маршруты, этапы маршрутов, точки посещения.
- **recommendations-service**: персональные рекомендации (на основе предпочтений и истории).
- **payments-service**: подписка Pro, интеграция с YooKassa, webhooks.

## Данные
- У каждого сервиса — своя БД PostgreSQL.
- Межсервисные связи идут по `user_id` и бизнес-идентификаторам (без FK между БД).

## Интеграции
- `trips-service` использует `user_id` из токена auth-service (BFF/gateway или прямой вызов).
- `recommendations-service` получает предпочтения через API auth-service и историю маршрутов из trips-service.
- `payments-service` подтверждает подписку и публикует статус в auth-service.

## Принципы
- Независимые деплой и схема БД.
- Контракты через REST (позже можно добавить события).
- Общие DTO фиксируются в документации и OpenAPI.
